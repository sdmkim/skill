중소기업 R&D 과제 데이터 분석 자동화 스킬

국가R&D 과제·성과·기업 원자료를 넣으면 매칭·통합, 데이터 점검, 협력유형별 과제수·연구비·성과 표까지 같은 절차로 만들어 주는 Claude 스킬입니다.

연구자가 협력과제 관련 원자료(과제·성과·기업 데이터)를 제공 시 통합 데이터를 만들고 데이터 점검 리포트와 협력유형별 기술통계를 제공하는 스킬을 만든다. 이것으로 주기적으로 반복되는 정부 R&D 협력과제 성과분석에 드는 시간을 줄이고, 같은 기준으로 데이터 분석을 수행할 수 있도록 한다.

내 업무와 선택한 과업

저는 현재 과학기술정책연구원에서 중소기업 기술혁신 연구를 주로 수행하고 있습니다. 그 중 정부 R&D 지원을 받은 중소기업의 성과분석은 주기적으로 반복되는 일입니다. 따라서 이 분석과정을 스킬로 만들면 업무 시간을 크게 줄일 수 있다고 판단하여 이 과업을 골랐습니다.

중소기업 R&D 협력과제는 중소기업이 대기업, 다른 중소기업, 대학, 출연연 등과 함께 수행하는 국가R&D 과제를 말합니다. 이 업무는 간단해 보이지만 생각보다 오랜 시간이 소요됩니다. 큰 규모의 과제데이터와 기업데이터를 매칭해 통합해야 하고, 데이터를 점검한 후 다양한 분류에 따라 연구비와 성과 등을 분석해야 하기 때문입니다. 따라서 이 과정 전체(매칭·통합, 데이터 점검, 파트별 기술통계)를 스킬로 만들어 보았습니다.

왜 스킬인가

기준이 과업그래서
누가 쓰나나(또는 같은 분석을 하는 동료)링크로 여러 사람이 쓰는 웹앱은 필요 없음
얼마나 자주주기적으로 같은 절차를 반복그때그때 Chat에 묻기보다 절차를 고정할 가치가 큼
입력과 출력내 PC의 대용량 엑셀 3개(약 270MB) → 통합 데이터와 결과 엑셀파일을 읽고 파일을 만드는 일이라 스킬에 맞음
데이터 민감도사업자번호, 연구책임자 정보, 유료 기업DB의 재무정보 포함외부에 올리는 웹앱보다 내 환경에서 도는 스킬이 안전
검증기존 통합본·결과표와 숫자를 맞춰 볼 수 있음AI가 틀려도 바로 알아챌 수 있음

절차

SKILL.md에 적힌 순서이며, 매번 이 순서대로 진행합니다. 숫자 계산은 모두 파이썬 스크립트가 하고, AI는 절차 지휘와 결과 해석만 맡습니다.

  1. 원자료 구조 파악파일별 시트 목록, 행·열 수, 열 이름만 봅니다. 개별 과제·기업 행은 화면에 띄우지 않습니다. 대상 과제 조건, 협력유형 정의, 연결 키, 재무값 단위와 기준 연도를 사용자에게 확인합니다.
  2. 설정 파일 작성대상 과제 필터, 협력유형 규칙, 연결 키, 붙일 성과·기업 변수, 제거할 식별 열을 JSON에 적습니다.
  3. 매칭·통합merge.py가 대상 과제 선별 → 참여기관 유형 → 협력유형 분류 → 성과 매칭 → 기업 매칭 → 식별 열 제거를 하고 매칭 리포트를 냅니다.
  4. 기술통계 실행describe.py가 점검 → 기술통계 → 엑셀 저장을 한 번에 합니다.
  5. 점검 결과 해석매칭률, 중복, 협력유형 번호 경계, 성과 빈칸 비율, 극단값, 단위를 보고 사용자에게 확인할 점을 알립니다.
  6. 검증기존 통합본과 열 단위로, 기존 결과표와 셀 단위(verify.py)로 대조합니다. 없으면 숫자 3개를 엑셀로 직접 맞춰 봅니다.
  7. 보고결과 파일과 3~5줄 요약을 전달합니다. 인과 해석은 하지 않습니다.

판단 기준

원자료는 AI가 읽지 않는다

대화에는 열 이름과 매칭 리포트, 요약 통계만 나옵니다. 계산은 스크립트가 해서 정확하고 다시 돌려도 같은 값이 나옵니다.

식별정보는 매칭에만 쓰고 버린다

사업자등록번호는 기업 매칭 키로만 쓰고, 대표자명·법인등록번호·주소·기관명·과제명·연구책임자 정보와 함께 통합 데이터에서 지웁니다.

유료 DB는 가상 데이터로 개발한다

이용약관이 확인되지 않은 기업 재무정보는 AI 작업공간에 올리지 않습니다. 같은 구조의 가상 기업데이터로 개발·시연하고, 실제 파일은 내 PC에서만 돌립니다.

매칭 결과는 숫자로 보고한다

매칭률, 중복 키, 미매칭 건수를 매번 출력합니다. VLOOKUP처럼 조용히 빠지거나 첫 값만 가져오는 일이 없게 합니다.

빈칸 처리는 명시한다

성과 빈칸은 "성과 없음(0)"으로 봅니다. 기존 피벗과 같은 정의이며, README 시트에 규칙을 남깁니다.

극단값은 표시만 한다

IQR×3 밖의 값을 세어 알리고, 삭제 여부는 연구자가 정합니다.

소수 사례는 일반화하지 않는다

과제수가 5 미만인 셀의 평균은 해석할 때 "소수 사례"라고 밝힙니다.

기술통계에서 멈춘다

회귀분석·유의성 검정·인과 해석은 하지 않습니다.

이것을 해도 되는가

애매했던 점

  • 사업자등록번호, 기관명, 연구책임자의 성별·학위가 들어 있는 과제 데이터를 AI 도구에 넣어도 되는가
  • 기업 파일에 대표자명, 법인등록번호, 주소가 있고, 개인사업자의 사업자번호는 개인정보가 될 수 있다
  • 기업 재무정보는 유료로 구매한 상용 기업DB 자료다. 이용계약상 외부 AI 서비스에 올려도 되는지 확인되지 않았다
  • AI가 만든 통계표를 논문·보고서에 그대로 써도 되는가

판단과 극복

  • 계산은 스크립트가 하고, AI에는 열 이름과 매칭 리포트, 집계값만 보이도록 절차를 설계
  • 사업자번호는 매칭에만 쓰고 식별 열 20개를 통합 데이터에서 삭제
  • 유료 기업DB 대신 같은 구조의 가상 기업데이터를 만들어 개발·시연. 생성기는 실제 기업DB를 열지 않고, 실제 분포도 학습하지 않음
  • 사람이 만든 통합본·결과표와 대조해 검증

남은 위험

  • 스킬을 개발하는 동안 원본 파일(유료 기업DB 포함)을 클라우드 AI 작업공간에 올렸다. 실제 업무에서는 기관이 허용한 도구 안에서 실행하거나 가상·가명 데이터를 써야 한다
  • 기업DB 이용계약 조건은 아직 확인하지 못했다
  • 협력유형 번호 경계(21위 54건, 22위 53건)처럼 정의에 따라 결과가 달라지는 부분은 사람이 정해야 한다
  • 극단값과 소수 사례는 사람이 판단해야 한다

실제 업무에 쓰려면 더 필요한 것

  • 기업DB 이용계약 확인. 외부 AI 도구 사용이 허용되는지 원내 데이터 구매 담당 부서에 확인한다.
  • 소집단 비공개 규칙. 기업 수가 5곳 미만인 셀의 재무 통계는 가린다. 집계값이라도 기업이 1~2곳이면 사실상 그 기업의 재무값이기 때문이다.
  • 기관 승인 도구에서 실행. 실제 데이터는 기관이 허용한 환경에서 돌리고, AI에는 열 이름과 집계값만 보이게 한다.
  • 정의 변경에 대비. 위탁기관 포함 여부나 유형 수 같은 정의가 바뀌면 설정 파일만 고쳐 다시 실행하고, 바뀐 정의를 보고서에 함께 적는다.
